# 本次独立入口与旧任务的区别

本任务由`AllEpithelium_PC.py`运行，所有准备、模型、日志和图表输出均位于本目录。旧CRC-only的work、模型和结果不作为本次模型输入，也不覆盖。

- 输入复用原始Release附件，大小、SHA256、ZIP CRC及7个文件清单均重新验证；完整矩阵为15,635基因×223,736细胞，497,539,060个非零项。
- 全部细胞通过校验后原样保留，不再进行CRC组织筛选。逐字段文本检查覆盖全部原始元数据，CNV原十进制文本也不改写。来源三分类只来自冻结审计表的精确多对一关联。
- 冻结排序列表在本次全池重新核对检出覆盖，1,998个排序基因全部满足至少10细胞检出。
- `reference/CRC_verified_fit_engine.R`保存已验证的旧引擎。派生引擎的稀疏矩、兼容、完整图排序函数和原生DDRTree调用保持不变；构建代码检查这一点并保存哈希。
- 根请求在共同几何生成后，按树端点的标本覆盖及替代端点的树上距离选择；宽身份仅记录覆盖，不以身份名称打分。选择函数不接收组织/CNV/功能字段。实际root_state、root cell_id和原生回退单独导出；若实际根未分开则如实报告。
- Slingshot使用全部同一批细胞、原始30维Harmony和原UMAP，起点取保存Monocle2实际根所在继承簇。精确线段搜索沿用上一轮经验证代码，保留原始全部顶点和细胞，不改原生拟合参数或已安装包；本任务重新运行软件对照。软件生成数据的逐值一致性不代替两套正式全量模型的一致性证明。
- 新增动态基因检验、模块及GO分析的预先参数见`ANALYSIS_PLAN.json`。以捕获单元/标本分箱表达及标本固定截距为核心，用报告链接单位的聚类协方差，不能把细胞当独立患者。组织/CNV/功能不参与基因选择或模块划分。
- 软件测试包括223,736行全量保留、来源规则、矩阵方向/顺序、分箱、等权、动态源表、合成图/根回退、精确投影和实际入口对照。正式树仍需独立数值检查，所有正式PNG/PDF仍需实际逐图逐页查看。

输入附件清单中的`main_fit_cells=150917`是上一轮输入交接附带的历史描述字段；本任务范围由本目录冻结规范、config、准备摘要及源名单定义，始终为223,736个细胞。
