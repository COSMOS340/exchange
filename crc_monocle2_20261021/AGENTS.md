# PC端执行约束

先读README、TASK_SPEC、RUN_ON_PC、RETURN_PROTOCOL。本仓库是研究交接，不是已完成的结果。

- 只在当前PC的新工作目录执行。读取实际OS、R/Python路径与版本，不猜Mac、WSL或Windows盘符，不沿用来源机器的绝对路径。
- 不启动GitHub Actions代替本地PC重计算。一次一个重任务；不用分块建模、不抽细胞、不降低固定细胞数。
- 全量指本包冻结生物学范围和上游资格后的150,917个CRC来源上皮，所有这些细胞均参加一棵树的拟合。存储压缩、文件传输分片和绘图栅格化不改变此范围。
- 正常/癌旁和原始元数据保留；无授权不恢复223,736全来源联合拟合，不自动把前13步重跑。CRC身份不等于恶性身份。
- 不用CNV组、CNV分数、功能得分选择根或排序基因。不得人为让Low在前High在后。
- 不重新QC、去双胞、重聚类、修改CNV标签、默默删异常细胞或选择有利队列。必要敏感性另表展示，与主结果分开。
- 保留现有Monocle2图排序及兼容修补；先验证再用。不要删掉它们后调用全细胞N×N距离矩阵。修补不等于分块建树，仍覆盖全部细胞。
- 输入、参数、代码和环境改变必须新建版本，检查已保存DDRTree断点绑定再恢复。遇错误先读日志，不重复启动、不改用Monocle3、不随机下采样。
- 本机已有运行任务时先核对进程所属目录与日志，不启动第二份。不要终止其他项目进程。
- 结果默认描述性。不能把细胞当患者重复；不新增星号/BEAM/tradeSeq/动态基因P值，除非用户另行确认设计。
- 先完成主Monocle2、数值检查和主图，再完成Slingshot对照及功能动态；失败项按实记录，不拿旧对象或模拟结果补齐。
- 每个主要阶段更新 `results/RUN_SUMMARY.md` 与 `results/04_日志和检查/progress.json`；前台告知真实阶段与已保存结果。运行时间长不等于卡死。
- 所有新增后处理代码保存在 `results/code/`，同时提交回传分支。记录Python包清单、R sessionInfo、git提交、OS和实际输入/输出哈希。禁止在日志输出认证令牌。
- 每张PNG和PDF全部页面必须实际查看，逐图阅读指南注明发现、无明确结果或失败原因，不能机械填“阳性”。
- 返回通过验收的结果，也可返回带明确失败状态的完整诊断包。不能把打包成功叫分析成功。
